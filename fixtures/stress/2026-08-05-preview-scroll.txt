Preview scroll cost — diff overlay's rendered document
======================================================

Machine: MacBook Pro (Mac14,6), Apple M2 Max, 32 GB, macOS 15.6, warm caches,
interactive session (not a quiet machine). Release build, --locked.

Command, per run (the app quits itself in the first frame's callback under
SOURCEFOUR_STARTUP_LOG, so each run is one process):

  SOURCEFOUR_STARTUP_LOG=1 SOURCEFOUR_FRAME_LOG=1 SOURCEFOUR_PREVIEW_STRESS=N \
    ./target/release/sourcefour --demo --scene preview --width 1280 --height 800

SOURCEFOUR_PREVIEW_STRESS=N repeats the demo document N times on the new side.
preview-build-ms is element construction for both panes in one frame.

Reading these numbers
---------------------
preview-build-ms is what the render pass spends building the panes. After
virtualization the per-block work moved out of the render pass and into the
list's layout, where only the blocks on screen (plus 400px of overdraw) are
built — so 0.003 ms is the panes going from 2,206 elements to two, not the
document becoming free. first-frame-ms is the honest end-to-end number: it
covers layout and paint, and it stops tracking document length.
